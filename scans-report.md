# Cover scan measurements

Generated by `scripts/measure-covers.ts`. Assumes each source image is a single, pre-cropped full wrap (back | spine | front) with no border beyond the trim edge, unless the manifest declares its bleed. Fold lines are found by edge detection, not assumed; header bands are detected as either a flat colour or a smooth vertical gradient (by where real cover art/photo texture starts, not by colour alone) — sloped/curved headers still need a follow-up pass. All colours are sRGB: an embedded ICC profile is converted to sRGB when the image is read (flagged in Notes), and an image with no profile is assumed to be sRGB already. Scans and templates whose embedded DPI isn't exactly 300 are rejected outright and don't appear below (see stderr). Rows named `template.*` are fan-made transparent templates: their layout is read from the alpha channel and their header band/colours with the same code as the scans. **Consensus** is the value most rows agree on: the largest group within 1 mm (sizes) or 1 point (shares of a panel) of each other, its median, shown with how many of the counted rows agree (`3/4`); fewer than two agreeing is no consensus (—). Rows that don't count are still listed: a **scale suspect** row (its size is more than 2.5 % off the case's, so its DPI tag, bleed or crop is wrong) counts for nothing, and a row whose fold lines were **estimated** (placed from the app's own spine width, so circular) counts only for its overall width and height. What a scan can't tell by itself (its bleed, its real DPI or trimmed height, hand-checked fold positions, or a reason to leave it out) is declared in scripts/scan-manifest.json. If `npm run compare:covers` has been run, a table also shows `app (rendered)`, the app's own render of that case measured with its fold positions known, and `app − Consensus` (mm or percentage points; `=`/`≠` for shapes; a colour distance, 0 to 441, for colours). It never counts towards the consensus.
